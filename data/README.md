# Data

No dataset files are committed. Everything under `artifacts/` is generated by the
pipeline and is git-ignored.

## Source

**COVID-QA** — [`deepset/covid_qa_deepset`](https://huggingface.co/datasets/deepset/covid_qa_deepset)
on the Hugging Face Hub (Möller, Reina, Jayakumar & Pietsch, *COVID-QA: A Question
Answering Dataset for COVID-19*, ACL 2020 NLP-COVID workshop). Licensed
Apache-2.0. Downloaded automatically on first run; ~15 MB.

The underlying articles come from [CORD-19](https://github.com/allenai/cord19)
(Allen Institute for AI).

## What it contains

| | |
|---|---|
| QA pairs | 2,019, annotated by biomedical experts |
| Source articles | 147 full-text CORD-19 papers |
| Corpus size | 3,863,049 characters of cleaned text |
| Answer format | text span + character offset into the article |
| Official splits | none — this project creates its own (see below) |

Article length is the reason this dataset was chosen: contexts run to a median
of ~30k characters, so chunking and retrieval are real problems rather than
formalities, and the character offsets let retrieval ground truth be *derived*
rather than assumed.

## Splits

COVID-QA ships as a single `train` split, so the splits here are created by this
project and are **document-level**, assigned by a stable hash of the document id
(`src/rag_system/data/covidqa.py::split_documents`):

| split | documents | questions |
|---|---:|---:|
| train | 102 | 1,157 |
| validation | 26 | 425 |
| test | 19 | 437 |

Splitting by document rather than by question is deliberate: several questions
share a source article, so a question-level split would let a fine-tuned reader
see the test article during training. Hash-based assignment (rather than a
shuffle) means adding or removing an article does not reshuffle the rest.

The **retrieval corpus spans all 147 documents** in every split — a retriever at
serving time searches everything, and restricting the index to test documents
would make retrieval artificially easy.

## Generated artefacts

`python scripts/prepare_data.py` writes to `artifacts/corpus/`:

| file | contents |
|---|---|
| `chunks.jsonl` | 4,844 chunks with `doc_id`, text and exact character offsets |
| `examples.jsonl` | questions, gold answers, split, and derived `gold_chunk_ids` |
| `documents.jsonl` | per-document metadata |
| `stats.json` | corpus statistics and the gold-label integrity check |
| `config.yaml` | the exact config used |

`python scripts/build_index.py` writes `artifacts/index/<model>__<strategy>_<size>_<overlap>/`
containing `chunks.jsonl`, `embeddings.npy`, `index.faiss` and a `manifest.json`
recording the chunking and embedding settings. The loader refuses to use an index
whose manifest disagrees with the requested config.

## Gold retrieval labels

A chunk is relevant to a question if it contains the annotated answer span
(character offsets, not string matching). If the span straddles a chunk boundary,
every overlapping chunk is marked relevant instead of the question being dropped.

Measured integrity: **2,000 / 2,019 (99.06%)** of derived gold chunks contain the
answer verbatim. The 19 exceptions are long answers (300–900 chars) that cross a
boundary — these are a genuine ceiling on extractive reader performance and are
counted as `chunk_boundary` failures in the error analysis rather than hidden.
